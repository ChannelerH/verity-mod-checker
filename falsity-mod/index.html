Setup and errors

Do not turn provider setup into a download problem

Commands and configuration are route-specific

The FALSITY [SMILEY] description exposes route-specific commands such as /connectfalsity, /falsitysetup, and /falsityconfig. Those are not universal Verity Mod commands. Verity BE, PnTMC Bedrock, Verity JE, and VERITY.exe have their own control and setup assumptions. Copying commands across projects is one reason players think the mod is broken even when they installed the wrong route.

If a command is missing, first prove that you installed the project that documents that command. Check the source page, Project ID, file ID, Minecraft version, and loader. Then test in a clean profile or clean world before adding other horror packs, shaders, resource packs, or server-side plugins.

AI, voice, and microphone features need their own checks

The Falsity project page describes optional external LLM, text-to-speech, and speech-to-text provider support, including OpenAI-compatible APIs, Gemini, Groq, Ollama, OpenRouter, and Whisper-compatible transcription. That means an API key, microphone, voice, or provider error can happen after the mod file itself is correct.

Do not paste API keys into random download pages, comments, or forms. Configure keys only in the game or provider flow that the project documents. If voice fails, prove typed chat first. If typed chat fails, prove the provider and config route. If the provider returns 401 or 429, use the API error pages instead of replacing a valid Falsity or Verity file with a mirror.

Setup order

Install Verity JE before debugging AI providers

Route first, API second

Verity JE uses an AI provider path after the Java mod loads. That means API connection failed, OpenRouter, Groq, Ollama, status 401, status 429, null replies, voice output, and server latency are second-stage problems. First prove the Java route: use the right Minecraft version, the right loader, the right JAR, and a clean profile. If the game crashes before the world opens, replacing an API key will not fix the crash. If the game opens and Verity responds with an API status code, then move to the provider page.

This is also why Verity JE is not the same thing as a Bedrock add-on. A Bedrock player imports MCADDON or MCPACK files into a world and activates behavior and resource packs. A Java player installs a JAR into a Forge or NeoForge profile and checks dependencies. Mixing those routes is one of the fastest ways to get a fake "not working" diagnosis from a perfectly real file.

Clean Java profile checklist

  • For stable: Minecraft 1.20.1, Forge, verity-5.7.3.jar, and the dependency records linked from the project.
  • For beta: Minecraft 1.20.1, Forge, Modrinth version 5ech0sTo, and a willingness to test a beta file.
  • For old NeoForge: Minecraft 1.21.1, NeoForge, record 8346795, and awareness that the branch is deprecated.
  • For Bedrock: stop here and use the Bedrock or MCPE route instead.

When to leave this page

Leave this page when the file identity is no longer the question. If Minecraft crashes, move to the Java setup or not-working guide. If Verity loads but returns status 401, 429, or a provider message, use the API guides. If your file is an MCADDON, MCPACK, APK, EXE, or modpack ZIP, stop treating it as Verity JE and use the Bedrock, MCPE, app-safety, or modpack route instead.

FAQ

Verity JE questions

Is Verity JE official?

The Verity JE project description says it is an official adaptation created and published with permission and agreement from ThatMob. This page does not claim ownership or host files; it maps that public route to exact source records so users avoid mirrors and wrong-edition packages.

Why is the beta on Modrinth but 5.7.3 is still the stable route?

Modrinth currently exposes 6.0.0-beta, while the stable 5.7.3 route remains the safer default for most Forge 1.20.1 players. A beta can be useful, but it should not replace the stable route in a general download answer until the source records and support context make that clear.

Can I use Verity JE on a server?

Start with a local proof first. Then use the server route to check matching loader, mod file, dependency list, client profile, API provider configuration, and latency expectations. A server setup should not be the first test if the single-player Java profile has not loaded.

Does a matching checksum prove the file is safe?

No. A checksum or metadata match proves identity with a recorded source file; it is not a malware verdict. It helps avoid copied filenames, stale mirrors, wrong loaders, and fake APK or EXE claims, but normal device and account safety rules still apply.
